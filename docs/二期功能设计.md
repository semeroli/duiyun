## 一、需求理解（用户故事）

| # | 谁 | 想做什么 | 为了什么 |
|---|---|---|---|
| 1 | 访客 | 在首页看懂「对韵是什么、能干什么」 | 决定要不要用 |

> **对联工具永远免登录可用。** 登录只解锁「存云端 / 留言」，
> 不登录照样能出下联。这是本产品的立身之本，任何改动都不能把工具关进登录墙后面。

## 三、架构与数据库

### 3.1 架构

```
浏览器
  ├─ 落地页 /            静态预渲染（谷歌大厂式信息层级 + 国风配色）
  ├─ 工具   /studio      现有对联工具原样搬迁
  ├─ 博客   /blog        服务端渲染，读 D1
  ├─ 账号   /login /register /me
  └─ 后台   /admin       仅 role=admin 可进
        │
        ▼  fetch /api/**
Cloudflare Worker（Next.js 15 + OpenNext）
  ├─ /api/generate       现有 AI 出句（不动）
  ├─ /api/auth/**        注册 / 登录 / 登出 / 改密
  ├─ /api/posts/**       文章读写
  ├─ /api/comments/**    评论
  ├─ /api/favorites/**   云端收藏
  ├─ /api/history/**     生成历史
  └─ /api/admin/**       后台专用
        │
        ▼  D1 绑定（wrangler.jsonc → d1_databases）
Cloudflare D1（SQLite）
  users / sessions / posts / comments / favorites / histories / rate_limits
```

**为什么选 D1**：和现有部署同平台、不额外花钱、不引外部依赖，
主站 `lwdy.de5.net` 与分享链接都能用。（已排除的选项：WorkBuddy 云服务会校验域名，主站用不了。）

### 3.2 表结构

见 `migrations/0001_init.sql`（7 张表 + 索引）。要点：

| 表 | 关键设计 |
|---|---|
| `users` | 邮箱唯一且大小写不敏感；`password_hash` 存 `pbkdf2$迭代次数$salt$hash`，**参数写在串里**，将来提高迭代次数不用改表；`must_change_password` 支持管理员重置后强制改密 |
| `sessions` | **只存 token 的 SHA-256**，库被拖走也拿不到可用 cookie |
| `posts` | `slug` 唯一；`status` 区分草稿/发布；正文 Markdown |
| `comments` | `parent_id` 支持两级回复；`status` 支持隐藏而不删 |
| `favorites` | `UNIQUE(user_id, item_key)`，同一副对联不会重复收藏；`data` 原样存整个收藏项（含 AI 写的解析） |
| `rate_limits` | 登录/注册/评论防刷，避免被脚本刷爆 |

### 3.3 安全设计

| 项 | 做法 |
|---|---|
| 密码存储 | PBKDF2-SHA256，每用户独立随机 salt，**绝不存明文、绝不记日志** |
| 会话 | 32 字节随机 token → Cookie 设 `HttpOnly` + `Secure` + `SameSite=Lax`；库里只存它的散列；30 天过期 |
| CSRF | `SameSite=Lax` + 所有写操作校验 `Origin` 头 |
| 越权 | 每条数据读写都带 `user_id` 约束；后台路由统一校验 `role='admin'` |
| 防刷 | 登录失败按邮箱+IP 计数；注册按 IP；评论 60 秒 1 条、每 IP 每小时 10 条 |
| XSS | 评论与文章正文**渲染前转义**；Markdown 只放行白名单标签，不执行内联脚本 |

> ⚠️ **一个待实测的风险**：Cloudflare Worker 免费版有 CPU 时间上限，密码散列是 CPU 密集操作。
> 计划用 PBKDF2 **100,000 次迭代**，如果线上报 CPU 超限，两条退路：
> ① 降到 50,000 次（安全性仍可接受，因为还有独立随机 salt）；
> ② 升级 Workers 付费版（约 $5/月）后可上到 OWASP 建议的 600,000 次。
> 这个我会在第一次上线后就实测并告诉你结论。

### 3.4 接口清单（新增部分）

```
POST   /api/auth/register          注册
POST   /api/auth/login             登录
POST   /api/auth/logout            登出
GET    /api/auth/me                当前登录者
```

### 6.2 与设计的差异

| 设计里写的 | 实际做的 | 为什么 |
|---|---|---|
| P0 只做落地页 + 路由 + 账号 | **顺带把博客列表/详情/管理后台也做了** | 导航上挂了「对韵博客」入口，只做个死链就是自找麻烦；博客读写是一体的，拆开做反而更费事 |
| 计划用 `wrangler d1 execute` 帮你跑建表 | **只能你手动粘** | 本机 wrangler 凭据是另一个 CF 账号（`qianmo`），看不到 `lwdy.de5.net` 那个账号下的库 |
| 建表 SQL 里保留 `PRAGMA foreign_keys` | 注释掉了 | D1 默认就开外键，控制台执行 PRAGMA 有可能报错并打断整段粘贴 |

### 6.3 两条踩过的坑（写给以后的自己）

1. **`route.ts` 不能多导出东西**。`app/api/posts/route.ts` 一开始把 `PostListItem` 类型和 `toListItem()` 函数一起导出了，构建会报
   「does not match the required types of a Next.js Route」。所以类型和纯函数都挪到了 `lib/posts.ts`。

2. **能引到客户端的文件绝不能碰 `getDb`**。`lib/posts.ts` 被客户端组件 `LatestPosts` 引用；
   如果把它和 `getDb` 放一个文件，`@opennextjs/cloudflare` 就会被打进浏览器包。所以数据库读操作单独放在 `lib/blogServer.ts`。

3. **`.open-next` 目录删不掉会让构建失败**。OpenNext 构建第一步是 `rmSync('.open-next')`，
   而本机这个操作会走「进回收站」的改写，几万文件的目录直接超时。
   正确姿势：先停掉 `preview` 服务（它占着文件），再用 PowerShell 的
   `[System.IO.Directory]::Delete($p, $true)` 直删。

### 6.4 本地实测结论（2026-10-13）

用 `opennextjs-cloudflare preview` + 本地 D1 跑通了完整链路：

| 测的东西 | 结果 |
|---|---|
| 注册 → 回显中文昵称 | ✅ 「王老师」完整无损 |
| 邮箱大小写不敏感 | ✅ `Wang@Example.com` 存成 `wang@example.com`，重复注册报 409 |
| 弱密码拦截 | ✅ 「密码至少 8 位」 |
| 错密码登录 | ✅ 401，且与「邮箱不存在」返回同一句话 |
| 登出后会话失效 | ✅ 库里会话行已删 |
| 跨站 Origin 写操作 | ✅ 403 |
| 发文 / 存草稿 / 发布 | ✅ 草稿不进公开列表，发布后前台立刻可见 |
| 非管理员发文 | ✅ 401/403 |
| Markdown 六项语法 | ✅ 见 `_mdselftest.mjs`，六项全过 |
| XSS（`<script>` / `onerror` / `javascript:` 链接） | ✅ 全部只显示成文字，无标签注入 |

**还没实测的**：PBKDF2 10 万次迭代在 Cloudflare 免费版 Worker 上的 CPU 耗时。
本地与生产环境 CPU 特性不同，量不出来 —— 上线后第一次注册时看返回耗时，
如果报 CPU 超限，把 `lib/auth.ts` 里的 `PBKDF2_ITERATIONS` 从 100000 调到 50000 即可（老密码不受影响，因为迭代次数写在散列串里）。
