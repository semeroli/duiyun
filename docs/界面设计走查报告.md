## 一、摘要：这是一套**底子很好**的设计

**先说不该动的。** 这套界面的资产是真实存在的，别推倒重来：

| 必须保留的资产 | 为什么 |
|---|---|
| **三套主题靠 CSS 变量切换**（`[data-theme]`） | 组件零改动换肤，是这套设计最聪明的决定。全站颜色类名 **708 处**，绝大多数走 token，没有出现「两种中性色混用」的经典脏乱 |
| **宣纸 / 朱印 / 竹帘的题材语言** | 底色、纹理、印章、卷轴轴头是一整套，不是零散贴图。改成通用 SaaS 风会失去辨识度 |
| **中文字体选择**（标题思源宋 + 正文霞鹜文楷） | 对联产品用宋楷是对的，而且回退链完整（拿不到在线字体就退系统宋体/楷体），不会白屏 |
| **圆角与阴影收敛** | 圆角只有 6px（71 处）+ 全圆（21 处）两档，阴影 3 档且全部走 `--shadow-rgb`。**比大多数项目干净** |
| **无障碍的两个硬底子** | 全站 `*:focus-visible` 兜底规则、`prefers-reduced-motion` 全局降级、**所有输入框都有可访问标签、没有任何"无名字的图标按钮"**（实测 `iconNoName: 0`、`inputsNoLabel: 0`） |

**分数式判断：视觉气质 85 分，设计系统 65 分，无障碍 55 分，移动端 50 分。**

**一句话结论**：现在的问题不是"不好看"，而是**三件可以量化、可以修的事**：

1. **一档颜色承担了两种职责** —— `--ink-faint`（弱化文字）既当正文级说明、又当装饰标注。它只有 **3.89:1**，达不到正文要求的 4.5:1，而全站 10–13px 的文字大量用它。**这是移动端 17 个/桌面端 15 个不达标元素的最大来源。**
2. **主输入框在手机上要滚动半屏才看得到** —— 顶部导航条（`NavBar` 单个组件）在手机上**自己换行成 4 行、合计 220px，占屏高 26%**，核心输入框落在 **489px（58% 屏高）** 处。这是最不像"移动优先"的地方。（此处初版曾误记为 262px/31%，根因也误记为"两套导航"，见 §6.2 订正说明。）
3. **中文用了 10px、11px 的字号**（源码 70 处 <12px）—— 中文没有词间空格，小字号比英文糊得多，10px 中文在手机上基本不可读。

## 三、字体

### 3.1 字体栈本身没问题

| 用途 | 声明 | 实测加载 |
|---|---|---|
| 标题 / UI（`font-song`） | Noto Serif SC → Source Han Serif SC → Songti SC → STSong → SimSun → serif | ✅ 21 个元素 |
| 正文（`font-kai`，body 默认） | LXGW WenKai → KaiTi → STKaiti → Kaiti SC → 楷体 → serif | ✅ 7 个元素 |

回退链完整，Windows 上有宋体/楷体兜底。**唯一的实务提醒**：字体走 `fonts.googleapis.com`，国内访问时常慢或不通 —— 好消息是有回退所以不会白屏，但**首屏字形会跳变**（先用宋体渲染，字体到了再换成思源宋）。建议后续把这两个字体自托管（放 `public/fonts/`），既稳定又是首屏性能收益。

### 3.2 真正的问题：**字号有 25 档，且中文用到了 10px**

源码里出现的显式字号：

```
8  9  10  10.2*  11  12  12.5  13  13.5  14  14.3*  15  16  17  18
20  22  24  26  28  30  32  34  36  40  42  56        （* 为渲染实测值）
```

**25 档**。而且分布是**倒挂**的：

| 区间 | 源码处数 | 判断 |
|---|---|---|
| < 12px | **70 处** | 🔴 中文可读性硬伤 |
| 12–13px | 107 处 | 偏多，但可接受 |
| ≥ 14px | 61 处 | 偏少 |

渲染实测（`/studio` @390px）：**14 个文字元素小于 12px**，最小的 10px：

```
10px   「智能对联生成器」    （顶栏 logo 副标题）
11px   「上联」「下联」      （输入卡标签）
11px   「平仄 / 词性 / 意境 / 典故」
11px   「AI 已接通 · Qwen/…」
10.2px 「对」「韵」          （页脚印章）
```

**中文没有词间空格，小字号下的字形密度远高于英文**：11px 中文的等效可读性大约相当于 9px 英文。而且这些恰恰是 3.89:1 的 `ink-faint` —— **又小又淡**，是最差组合。

另外 `text-[12.5px]`、`text-[13.5px]`、`text-[14.3px]` 这类**半像素字号**会造成亚像素取整不一致（有的屏幕渲染成 12px、有的 13px），是字号失控的信号。

### 3.3 ✅ 建议：收敛到 **8 档**，并立一条硬规则

| 档位 | 用途 | 对应现在的 |
|---|---|---|
| **12px** | 最小单位：时间戳、脚注、页脚 | 8 / 9 / 10 / 10.2 / 11 |
| **13px** | 标签、按钮、导航、辅助说明 | 12 / 12.5 / 13 / 13.5 |
| **15px** | 正文、卡片说明 | 14 / 14.3 / 15 |
| **18px** | 小标题（h3/h4） | 16 / 17 / 18 |
| **22px** | 章节标题（h2） | 20 / 22 / 24 |
| **28px** | 页面标题（h1） | 26 / 28 / 30 |
| **34px** | 工作台主输入（桌面上是 34px） | 32 / 34 / 36 |
| **42px** | 落地页主标题（桌面） | 40 / 42 / 56 |

**硬规则（写进项目规范，比刻度表更重要）：**

1. **中文最小 12px**。真需要更小的视觉，用**降低字重或提高字距**，不要降字号。
2. **半像素字号一律禁止**（`12.5px` → `13px`）。
3. **字号只用这 8 档**，不用 `text-[17px]` 这种一次性值。
4. **不要靠 `font-weight: 700` 堆层级**。现在标题用 600、正文 400，这个是对的，保持。层级优先靠**字号 + 颜色 + 留白**。

### 3.4 一个细节：`📖` emoji

`components/UpperInput.tsx` 的「📖 对联知识小贴士」用了 emoji。在国风版式里，emoji 会随系统/浏览器渲染成完全不同的风格（Apple 是彩色拟物、Windows 是扁平、部分 Linux 缺字形变方框），**和整套宋楷印章的语言不搭**。建议换成一个内联 SVG 书卷图标，或直接去掉 —— 同排的「生成卡片分享」就没有图标，去掉反而更整齐。

## 四、形态（圆角 / 阴影 / 间距）

**这一项是三块里做得最好的，只需微调。**

| 维度 | 现状 | 判断 |
|---|---|---|
| 圆角 | `rounded-md`(6px) ×71、`rounded-full` ×21、`rounded-lg`(8px) ×1、`.paper-panel` 6px | ✅ 已收敛到两档。**只把那 1 处 `rounded-lg` 改回 `rounded-md`** |
| 阴影 | `shadow-seal` ×10、`shadow-lift` ×9，全部基于 `--shadow-rgb` | ✅ 主题自适应，好 |
| 间距 | 以 4px 为主，混用少量 3/5/7px | ⚠️ `gap-3.5`、`py-2.5`、`px-3.5` 这类混合值偏多，建议统一到 **4 的倍数**（`gap-4`、`py-3`、`px-4`） |
| 固定高度 | `h-[…]` **33 处** | ⚠️ 内容可能换行的容器应改 `min-h-`，否则窄屏会溢出 |

**微交互一处要改**：`components/ui.tsx` 的按钮基类是

```
transition-all duration-200  +  hover:brightness-110  +  hover:shadow-lift
```

`transition-all` 会把**所有**属性（含 box-shadow、filter）都纳入过渡，阴影和滤镜都是**重绘**属性（不是 GPU 加速的 `transform`/`opacity`）。手机上点一排按钮会有明显掉帧。

**建议**：保留 `active:translate-y-[1px]`（transform，好），把悬停反馈改成 `hover:-translate-y-px` + 颜色变化，去掉 `hover:shadow-lift` 的过渡，并把 `transition-all` 收窄成 `transition-[transform,background-color,border-color,color]`。

## 五、无障碍（按优先级）

### 🔴 P0 — 键盘用户根本看不见焦点在哪

**实测方法**：真实键盘 `Tab` 遍历（不能用 `el.focus()`，那样测不出 `:focus-visible`）。

| 页面 | Tab 走过元素 | 无可见焦点 |
|---|---|---|
| `/studio` @390 | 19 | **2** |
| `/login` @390 | 13 | **2** |

命中的正是最要紧的控件：

```
✗ <textarea>「请输入上联…」      outline=solid 2px rgba(0,0,0,0)   ← 全站最核心的输入框
✗ <button>「📖 对联知识小贴士」   outline=solid 2px rgba(0,0,0,0)   ← Btn 组件
✗ <input>「you@example.com」     outline=solid 2px rgba(0,0,0,0)   ← 登录页
✗ <input>「••••••••」            outline=solid 2px rgba(0,0,0,0)   ← 登录页
```

**根因**：`globals.css` 里有一条全局兜底 `*:focus-visible { outline: 2px solid var(--cinnabar) }`，
它本身是**正确且值得表扬**的做法 —— 但有三处把它覆盖掉了：

| 位置 | 写法 | 后果 |
|---|---|---|
| `components/UpperInput.tsx:73` | `outline-none` | 主输入框焦点环被抹成透明 |
| `components/AuthForm.tsx:168` | `outline-none focus:border-cinnabar/60` | 只有 1px 边框变色，几乎看不出 |
| `components/AdminClient.tsx:466` | 同上 | 同上 |
| `components/ui.tsx:21` | `focus-visible:outline-none` | **所有 `Btn` 组件**都没有焦点环，且**没有替代样式** |

（`outline-none` 在 utilities 层，全局规则在 base 层 → utilities 优先级更高，所以全局兜底被吃掉了。）

**修法（二选一，推荐 A）**

**A. 最省事：让全局规则优先，删掉 `outline-none`**

```diff
- "focus-visible:outline-none active:translate-y-[1px]";
+ "active:translate-y-[1px]";
```
```diff
- const INPUT = "… outline-none transition-colors … focus:border-cinnabar/60";
+ const INPUT = "… transition-colors focus-visible:border-cinnabar/60";
```
```diff
- className="w-full resize-none bg-transparent font-song text-[26px] … outline-none placeholder:…"
+ className="w-full resize-none bg-transparent font-song text-[26px] … placeholder:…"
```

**B. 若因某种原因必须保留 `outline-none`，则必须补一个等价替代**（且要满足 3:1 可见度）

```css
/* 双环：内圈用面板色"切开"，外圈才是焦点色 —— 在浅色和深色底上都看得见 */
.focus-ring {
  outline: 2px solid var(--cinnabar);
  outline-offset: 2px;
}
```

> 验证口径：改完重跑 `node _audit/focus.mjs <url> 390 844`，**要求两个页面都是 0 个**。

### 🟠 P1 — 输入框边框看不出来（对比度 1.28:1，需 3:1）

登录页实测：`border-line` 的输入框，边框色对面板只有 **1.28:1**，而输入框底色 `#fffdf9` 与页面底色 `#faf7f2` 只差 **1.02:1** —— **两者都几乎为零，等于这个输入框没有边界**。截图里也能明显看出邮箱框像一段"漂浮的文字"。

**修法**：给输入框单独一个 token（不要污染 `--line`）

```css
:root, [data-theme="silk"] {
  --line-input: rgba(44, 36, 22, 0.5);      /* 3.01:1 ✅ */
}
[data-theme="spring"] {
  --line-input: rgba(150, 45, 30, 0.6);     /* 3.06:1 ✅ */
}
[data-theme="night"] {
  --line-input: rgba(237, 223, 192, 0.4);   /* 3.08:1 ✅ */
}
```
```ts
// tailwind.config.ts
lineInput: "var(--line-input)",
```
然后把 `AuthForm` / `AdminClient` / `UpperInput` 里的 `border-line` 换成 `border-lineInput`。

## 六、响应式与移动优先

### 6.1 断点分布

| 断点 | 处数 |
|---|---|
| `sm:` (640) | **4** |
| `md:` (768) | **~65** |
| `lg:` (1024) | 6 |
| `xl:` (1280) | 6 |

**读法**：不是"桌面优先"，但也**不是真正的移动优先** —— 而是**只有一个主转折点（768px）**。
390–767 这一整段（涵盖了 iPhone 全系、多数安卓旗舰、竖屏平板）**没有中间档**：
大屏手机和 320px 小屏手机用的是同一套布局，所以小屏被压得最狠。

**建议**：给三类地方补 `sm:` 档
- 「数据底气」统计区：已经是 `grid-cols-2 md:grid-cols-4`，可在 `sm:` 就上 4 列
- 落地页的示范卡、特征卡：`sm:grid-cols-2` 已有，补 `sm:grid-cols-3` 的中间态
- 工作台在 640–767 保持单列是对的，不要提前变两栏

### 6.2 🔴 移动端最实的问题：顶部吃掉了 26% 的屏幕

> **⚠️ 本节已订正（初版有误）。** 初版写「262px / 31%」，并把根因归为「`/studio` 同时挂了两套导航
> —— `SiteHeader` 与 `NavBar`」。**这个根因是错的。** 复核 `app/studio/page.tsx:285` 后确认：
> **`/studio` 只渲染了 `NavBar` 一个 header，页面里根本没有 `SiteHeader`**
> （`SiteHeader` 只出现在 `/`、`/blog`、`/login`、`/register`）。
> 262px 是测量脚本把 `header` 和**它内部的 `<nav>`**（类型切换条）重复相加得来的。
> 脚本已修（现在会把嵌套子条排除、单独列出说明），订正后数据如下。

`/studio` @390×844 实测（脚本订正后）：

```
header（NavBar，.sticky.top-0）    高 220px   ← 全页唯一条
   └─ nav（类型切换条，嵌在其内）   高  42px   ← 已含在 220px 内，不重复计
────────────────────────────────────────────
真实遮挡                           220px  = 屏高的 26%

首个输入框 top = 489px   （= 屏高的 58%）
```

也就是说：**用户在手机上打开工具，顶部先被占掉四分之一屏；输入框还要再往下 269px 才出现**
—— 而这个输入框是这个产品的全部价值所在。

**真正的根因：`NavBar` 这一个组件，在 390px 下自己换行成了 4 行。**

`NavBar` 主容器是 `flex flex-wrap`（`components/NavBar.tsx:48`），它同时塞了三块东西：

| 行 | 内容 | 约高 |
|---|---|---|
| ① | logo（实测 124×41）+ 右侧工具第 1 行 | 41 |
| ② | 右侧工具第 2 行 | 36 |
| ③ | 类型切换条（`order-last w-full`，强制独占一行） | 42 |
| ④ | 当前类型说明小字（`text-[11px]`，可能占 2 行） | ~35 |

**右侧工具一行放不下，是整条问题的起点**。实测这几个按钮的宽度：

```
对韵博客 74  +  音效 59  +  学习模式 72  +  收藏 46  +  主题 46  +  登录 46  +  注册 48
────────────────────────────────────────────────────────────────────────────
≈ 391px（还没算 gap-1 的间距）     > 390px 屏宽  ⇒ 必然折行
```

**修法（本轮已按此实施）**

1. **手机端把「音效 / 学习模式 / 收藏 / 主题」收进一个「设置」抽屉** —— 它们都不是高频操作。
   手机上只留 `logo + 对韵博客 + 账号`。这一条把右侧工具从 2 行压回 1 行。
2. **类型切换条保持独占一行** —— 它是一级操作（传统/谐音/金句），不藏。
3. 类型说明小字在手机上**限一行**（`truncate`），需要看全文的进设置抽屉。

**目标：让主输入框落在 300px 以内（约 1/3 屏）。**
