### 为什么不能用带注解的那份

带注解的 `0001_init.sql` 长这样：

```sql
CREATE TABLE IF NOT EXISTS users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  email         TEXT NOT NULL COLLATE NOCASE,   -- 登录名，唯一（大小写不敏感）
  nickname      TEXT NOT NULL,                  -- 显示名
  ...
```

它的注解是写在**行尾**的。而 SQLite 认为 `--` 后面**直到这一行结束**都是注解。
如果粘贴时换行丢了（控制台把整段压成一行），那句注解就会把它**后面整段代码**都吃掉，
数据库只看到半句 `CREATE TABLE ... (`，于是报 `incomplete input: SQLITE_ERROR`。

这个结论不是猜的 —— 见 `_sqlcheck.mjs`：同一个文件保留换行能建出 8 张表，
压成一行就报错；换成没有注解的 `console` 版，压不压成一行都能建出来。

### 🔴 「控制台说没数据，网站说有账号」是怎么回事

**证据长什么样**（2026-10-13 真实遇到过）：

| 谁在查 | 查到什么 |
|---|---|
| 你在 D1 控制台跑 `SELECT id, email, nickname, role, status FROM users` | **0 行**（提示「此查询未返回数据」） |
| 网站自己跑 `SELECT COUNT(*) FROM users` | **2** |

同一个库里 `users` 表不可能一边 0 行、一边 2 行。**必然是你在看的库 ≠ 网站读的库。**

> 注意区分：**表不存在** 会报 `no such table: users`（那说明库是对的、只是没建表）；
> **返回 0 行** 说明表建了、就是没数据 —— 是两码事。

**怎么找对库（唯一的可靠办法）**

1. 左侧栏进 **D1**（新版在 `Storage & Databases` 下面，老版在 `Workers & Pages` 里）
2. 把它列出来的数据库**逐个点开**，在 SQL 框里跑这一句：

```sql
SELECT COUNT(*) AS n FROM users;
```

3. **哪个返回 `2`（或任何非 0 的数字），那个就是网站正在用的库。**
   留在那个库里跑提权 SQL。返回 `0` 的、或报 `no such table` 的，都不是。
4. 🔑 **对不上的时候，先看网站那边现在是几**：浏览器直接打开
   `https://lwdy.de5.net/api/auth/me?selfcheck=1`，里面的 `users` 值就是标准答案。
   你控制台的 `COUNT(*)` 要和它一致 —— **一致就说明库选对了**。
5. 交叉验证：在库的页面看**浏览器地址栏**，尾部那串 UUID 应该等于
   `c770053a-5cb3-42e0-bd14-0a3d5919e241`（这是写死在 `wrangler.jsonc` 里的绑定 ID）。

**如果每个库都返回 0、或者列表里根本没有别的库** ⇒ 说明你现在登录的 Cloudflare 账号
可能不是网站所在的那个账号（对韵这个 Worker 挂在另一个账号下）。这种情况别自己折腾，告诉我。

> ⚠️ 提权 SQL 跑对库之后，**必须退出登录再重新登录一次** —— 菜单里的「管理后台」
> 是登录那一刻按角色渲染的，不重登看不到。

> 建表语句是写成 `CREATE TABLE IF NOT EXISTS`（存在就跳过）的，
> 所以**同一份粘两遍也不会坏**。不放心就再跑一次。
