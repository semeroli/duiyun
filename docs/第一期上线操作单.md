### 为什么不能用带注解的那份

带注解的 `0001_init.sql` 长这样：

```sql
CREATE TABLE IF NOT EXISTS users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  email         TEXT NOT NULL COLLATE NOCASE,   -- 登录名，唯一（大小写不敏感）
  nickname      TEXT NOT NULL,                  -- 显示名
  ...
```

它的注解是写在**行尾**的。而 SQLite 认为 `--` 后面**直到这一行结束**都是注解。
如果粘贴时换行丢了（控制台把整段压成一行），那句注解就会把它**后面整段代码**都吃掉，
数据库只看到半句 `CREATE TABLE ... (`，于是报 `incomplete input: SQLITE_ERROR`。

这个结论不是猜的 —— 见 `_sqlcheck.mjs`：同一个文件保留换行能建出 8 张表，
压成一行就报错；换成没有注解的 `console` 版，压不压成一行都能建出来。

## 万一出问题

| 现象 | 多半是什么原因 | 怎么办 |
|---|---|---|
| 建表时报 `incomplete input: SQLITE_ERROR` | 粘的是带注解的那份（`0001_init.sql`），且粘贴时换行丢了，`--` 注解把它后面的代码吃掉了 | 改用 `0001_init.console.sql`（无注解版），并用记事本复制 |
| 建表「执行成功」但一张表都没建出来 | 同上，整段都被注解吃掉了（不报错，因为整段都成了注解） | 同上 |
| 注册提示「站点数据库还没建好」 | 第 1 步的建表还没做 | 回第 1 步执行 `0001_init.console.sql` |
| 注册后菜单里没有「管理后台」 | 第 2 步那句 SQL 的邮箱写错了 | 重跑一遍 `UPDATE`，邮箱不区分大小写 |
| 提示「尝试太频繁了」 | 防刷机制，密码试错次数太多 | 等 15 分钟自动解除；着急的话在 D1 执行 `DELETE FROM rate_limits;` |
| 博客页显示「还没有发布的文章」 | 正常，说明还没有已发布的文章 | 去管理后台写一篇，点「发布」再「保存」 |
| 想知道数据库到底通不通 | — | 浏览器打开 `/api/auth/me?selfcheck=1`，看 `db.ok` 是 `true` 还是 `false` |

> 建表语句是写成 `CREATE TABLE IF NOT EXISTS`（存在就跳过）的，
> 所以**同一份粘两遍也不会坏**。不放心就再跑一次。
